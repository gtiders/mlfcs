# 文档规范

## 背景

定义页面模板、术语、状态元数据、双语镜像、代码验证、链接和美元符号数学公式规范。 - 两种语言首页维护项目介绍，并生成 README 核心区域。 - Theory 维护推导，Concepts 维护对象模型，Tutorials 维护学习工作流，How-to 维护具体任务。 - Reference 维护公共签名，Examples 维护可复现证据，Roadmap 维护未实现工作。 Theory 页面使用“动机、定义、推导、在 MLFCS 中的实现、数值注意、相关页面、参考文献”。Tutorial 使用“目标、前置条件、准备、步骤、结果、解释、常见问题、下一步”。How-to 使用“问题、解决方法、解释、限制、相关页面”。 Markdown 行内数学使用 `$...$`，独立公式使用 `$$...$$`。中英文页面共享路径、标题层级、公式、代码、状态和案例语义；翻译不得改变数值约定。 公共 API 修改必须在同一提交中更新 Reference 和所有受影响工作流。算法修改必须在发布前更新 Theory、Validation 和对应案例证据。

## 职责与边界

本页描述的是内部架构约束，不构成额外公共 API。底层结构和 interaction 模块不得反向依赖拟合、物理工作流或 IO。

## 实现原则

物理身份使用明确的数据结构表达；昂贵映射和对称分析在顶层构造一次并缓存；格式专属限制停留在 writer 边界。

## 验证要求

每次迁移或算法替换都应保持参数排列、预测力和 IFC 语义，并通过架构依赖检查、专项单元测试和真实案例回归。

## 维护规则

移除旧实现时不保留无期限兼容分支。研究原型与生产模块分离，只有通过数值和资源验收的方案才能进入稳定路径。
