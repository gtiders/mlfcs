# 与其他软件的关系

MLFCS 位于“原子力计算”和“声子、非谐性及输运后处理”之间。它不替代电子结构程序，也不重新实现所有声子和输运求解器；它负责把结构与原子力转换成经过对称约化、约束和验证的力常数。

```text
DFT / MLIP / ASE Calculator
            │ structures + forces
            ▼
          MLFCS
 finite difference / fitting
 symmetry / constraints / IFC
            │ validated force constants
            ▼
phonopy / phono3py / ShengBTE / ALAMODE
```

## ASE：公共结构和计算器边界

MLFCS 使用 ASE `Atoms` 表示 primitive、reference supercell、位移结构和训练快照，并通过 ASE `Calculator` 接收直接计算的力。ASE 负责通用结构容器、文件读取和 calculator 协议；MLFCS 负责周期结构关系、interaction、orbit、位移计划、拟合与 IFC。

因此 MLFCS 不绑定某个 DFT 或机器学习势。直接 calculator 可以驱动有限差分和 SSCHA；对 VASP、Quantum ESPRESSO 等外部任务，可用 `sow()` 生成结构，在外部完成计算后用 `reap()` 回收力。

## phonopy：谐性声子与结构约定

phonopy 擅长谐性动力学矩阵、声子谱、态密度和成熟的超胞工作流。MLFCS 可以生成 phonopy-compatible FC2，但声子求解仍由 phonopy 完成。

最稳妥的做法是先确定 phonopy 使用的 primitive 与 supercell，再将它们传给 MLFCS。phonopy FC2 是目标超胞上的稠密表示；MLFCS 原生 IFC 使用 primitive site 与精确整数平移，因此导出需要显式 target realization。

## phono3py：三声子与热输运

phono3py 负责 FC3 相关的三声子散射、寿命和晶格热导率。MLFCS 构造 FC2/FC3 并可写出 phono3py-compatible HDF5；q 网格、散射过程和 BTE 求解仍由 phono3py 完成。

外部 HDF5 保存目标超胞的稠密数组，不保存 MLFCS 原生 exact-$R$ interaction。比较不同路线时，应在同一 target supercell 上比较物理数组，而不是文件 block 顺序。

## ShengBTE：文本 IFC 与 BTE

ShengBTE 使用特定 FC2、FC3 和可选 FC4 文本格式。MLFCS writer 转换原胞标签、整数平移、Cartesian 分量和单位，但不生成或猜测用户 `CONTROL` 中的物理参数。

block 顺序不是唯一物理身份。两个合法 writer 可以产生不同顺序，必须按原子标签、整数平移和 tensor component 对齐后比较。

## ALAMODE：FCSXML 与后处理

ALAMODE 的 `alm` 可以拟合力常数，`anphon` 可以进行声子和非谐后处理。MLFCS 与它有部分能力重叠，但内部表示和拟合基底不同。

MLFCS 可以写出 FC2–FC4 FCSXML。ALAMODE 专属的 27-image 编码只存在于 writer 边界，不反向决定 MLFCS 内部 interaction、cutoff 或拟合语义。

## hiPhive：相近问题，不同内部模型

hiPhive 同样使用 cluster、orbit、对称约化和力拟合，并提供 ForceConstantPotential。MLFCS 共享代表 interaction 和 orbit 展开等通用数学思想，但没有复制其 cluster-space 实现。

MLFCS 使用 primitive exact-$R$ IFC、单 reference 拟合、Wick 拟合坐标和 Taylor 物理输出。hiPhive FCP 更接近可直接求力的势模型；MLFCS `ForceConstants` 首先是物理 IFC 数据。

## DFT 与机器学习势：力的来源

VASP、Quantum ESPRESSO、CP2K 或 MACE、NEP、PolyMLP 等只负责为给定结构提供力。MLFCS 不控制它们的精度设置，也不能用拟合误差掩盖不一致的 DFT 参数、错误原子顺序或未收敛的力。

可复现计算应保存结构、calculator 参数、原始力与单位、configuration ID、原子顺序、MLFCS 版本、cutoff、body order 和约束设置。

## 应该从哪个软件开始

如果结果最终交给 phonopy、phono3py、ShengBTE 或 ALAMODE，应先确定该软件的 primitive、supercell 和单位约定，再建立 MLFCS reference。MLFCS 可以验证合法等价表示，但从目标软件的结构开始可减少导出歧义。
