# MLFCS 实现路线图

## 阶段一：基础契约

- 固定 primitive/reference 输入规则；
- 固定 `StructureRelation`、`PeriodicIndex` 和 sparse IFC 语义；
- 固定 HDF5 版本、单位、张量基和元数据；
- 为所有公共函数提供完整签名、参数说明和错误条件。

验收重点是原子重排、原点平移、非对角整数超胞和严格等价导出不改变物理结果。

## 阶段二：计算内核

- 统一有限差分、拟合、ASR 和重构使用的 cluster 映射；
- 保持高阶计算稀疏，避免隐式稠密中间量；
- 将旋转求和规则作为独立 FC2 后处理或明确的约束组件；
- 记录拟合诊断、约束秩、残差和耗时。

## 阶段三：有限温度方法

- SSCHA 只负责内部采样、力评估、有效 FC2 更新和诊断历史；
- SCPH 只负责 loop 自洽修正、温度延续和有效 FC2；
- 两者都返回标准 `ForceConstants`，共享普通 writer；
- 温度序列统一排序，并支持明确的 continuation 和 warm start。

## 阶段四：IO 与案例

- 先验证 native HDF5 往返；
- 再验证 phonopy、phono3py、ShengBTE 和 ALAMODE 的格式语义；
- 每个案例将输入、运行脚本、结果摘要、绘图脚本和第三方参考分开组织；
- 计算产生的大型中间文件不自动进入核心提交。

## 阶段五：性能与维护

- 结构匹配、spglib 和周期搜索只在结构关系建立时执行；
- Gram 系统和高阶展开使用流式或稀疏路径；
- 缓存必须在日志中明确报告命中与重建；
- 任何数值优化都必须有前后案例回归、内存峰值和运行时间记录。

## 回滚要求

每个跨模块修改都必须先形成独立提交或标签。修改不得依赖工作区中未跟踪的力常数文件才能运行，失败时应能恢复到上一个公共 API 和数值基线。
