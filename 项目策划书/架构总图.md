# MLFCS 架构总图

## 1. 分层原则

依赖方向只能从上层指向下层，底层不能反向调用具体 writer、examples 或某个外部软件的格式推断。

```text
用户 API 与案例
        ↓
有限差分 / 拟合 / SSCHA / SCPH
        ↓
约束与重构
        ↓
稀疏 IFC 与结构关系
        ↓
周期几何与整数晶格运算
        ↓
ASE / spglib / NumPy 等基础库
```

IO 是面向结果对象的侧向适配层：

```text
ForceConstants + ExportView → HDF5 / phonopy / ShengBTE / ALAMODE
```

writer 不负责重新选择 primitive，不负责猜测原子顺序，也不负责重新执行 orbit 或拟合。

## 2. 主要职责

### 结构层

结构层负责验证元素组成、原子数量、周期晶格和 primitive/reference 的严格对应关系，并保存用户 reference 的原子顺序。

### 周期几何层

周期几何层负责最近镜像、邻居集合、截断稳定性和几何缓存。它不改变 IFC 的物理标签，也不把格式专用的镜像编码写入力常数本体。

### IFC 层

IFC 层保存 lattice-labelled sparse force constants。第一个 site 是零平移锚点，其余原子由 primitive site 和整数平移表示。

### 计算层

有限差分直接在用户 reference 顺序上产生力常数。拟合器使用结构关系建立设计矩阵。SSCHA 和 SCPH 只返回有效 FC2，并复用标准 `ForceConstants` 导出接口。

### IO 层

IO 层先构造 `ExportView`，验证 source/target 表示严格等价，再按目标格式物化必要的稠密或镜像数组。原生 HDF5 保存稀疏物理语义，格式要求不能反向改变内部数据模型。

## 3. 组织边界

`src/mlfcs` 保存可复用实现，`tests` 保存快速、确定性的行为测试，`examples` 保存完整案例和第三方对照，`项目策划书` 保存设计决策、实现路线和验收记录。案例产生的大型计算结果不因方便而复制进核心模块。
